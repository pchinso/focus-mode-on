# `SPEC.md` — Sistema Automatizado de Productividad y Contexto Diario con IA

## 1. Visión General del Sistema

El objetivo de este sistema es automatizar por completo la preparación metodológica de la jornada laboral de un perfil directivo, disperso o con alta carga de gestión de equipos.

Cada día a las **09:00 AM**, un agente central basado en un Modelo de Lenguaje de Gran Tamaño (LLM, ej. _Claude 3.5 Sonnet_) recopila información fragmentada de múltiples fuentes (memoria interna, tareas, chats de WhatsApp, calendario, estados de proyectos) para sintetizar un "Dashboard del Día" hiper-personalizado que optimice la toma de decisiones, prevenga bloqueos y ordene las prioridades.

## 2. Arquitectura de Datos y Fuentes de Información

El sistema debe conectarse a las siguientes fuentes mediante APIs o webhooks para consolidar el contexto:

- **Módulo 1: Base de Conocimiento / Memoria a Largo Plazo**
    
    - _Origen:_ Base de datos vectorial o archivo Markdown persistente (`memoria_proyectos.md`).
        
    - _Contenido:_ Histórico de decisiones clave, objetivos trimestrales, contexto general de la empresa y estado actual de proyectos.
        
- **Módulo 2: Gestor de Tareas (Backlog)**
    
    - _Origen:_ Daily notes de Obsidian, tareas del INBOX y DONE
        
    - _Contenido:_ Listado de tareas completadas el día anterior, tareas pendientes y backlog general.
        
- **Módulo 3: Captura de WhatsApp (opcional no necesario actualmente)**
    
    - _Origen:_ API de WhatsApp Business Cloud o pasarelas de automatización (ej. _ManyChat_, _Zoko_ o scripts sobre _Baileys_ / _Puppeteer_).
        
    - _Contenido:_ Volcado en texto plano de los mensajes y conversaciones grupales/individuales con el equipo de las últimas 24 horas.
        
- **Módulo 4: Calendario**
    
    - _Origen:_ API de Google Calendar y Microsoft Outlook.
        
    - _Contenido:_ Eventos, reuniones y huecos libres programados para el día en curso.
        

## 3. Lógica del Flujo de Trabajo (Paso a Paso)

El _script_ principal se ejecuta vía un _cron job_ diario a las 08:45 AM para asegurar que el informe esté listo y formateado exactamente a las 09:00 AM.

### Paso 1: Recopilación de Contexto e Historial

- Se extrae el resumen del día anterior.
    
- Se consulta la base de tareas para identificar qué se cerró con éxito y qué quedó marcado como pendiente.
    
- Se añade el contexto general del negocio desde el módulo de memoria.
    

### Paso 2: Análisis Automatizado de WhatsApp

- El sistema procesa la transcripción de los chats grupales y privados del equipo.
    
- **Lógica de filtrado (Prompting):** Se instruye al LLM a ignorar el ruido (saludos, comentarios informales, memes) y a extraer únicamente:
    
    1. Peticiones directas al usuario.
        
    2. Bloqueos reportados por miembros del equipo.
        
    3. Hitos logrados o entregas realizadas.
        

### Paso 3: Evaluación de la Carga del Calendario y Clasificación del Día

- Se calcula el número total de horas ocupadas en reuniones entre las 09:00 y las 18:00.
    
- **Reglas de negocio basadas en disponibilidad:**
    
    - _Día Abierto (Reuniones < 2h):_ El sistema asigna etiqueta **"Trabajo Profundo" (Deep Work)** y programa bloques largos para proyectos estratégicos.
        
    - _Día Parcialmente Ocupado (Reuniones 2h - 5h):_ El sistema asigna etiqueta **"4 Horas Productivas"** centrándose en tareas de esfuerzo medio.
        
    - _Día Saturado (Reuniones > 5h):_ El sistema asigna etiqueta **"Tareas Cortas" / Microgestión**, priorizando llamadas rápidas, respuestas breves y acciones de un solo clic.
        

## 4. Estructura e Interfaz del Output (El "Dashboard Diario")

El entregable final que consume el usuario en la nota diaria de Obsidian debe seguir de manera estricta la siguiente estructura:

### 📑 [Día/Mes/Año] - Tu Copiloto Diario

#### 1. Tipo de Jornada y Enfoque

- **Estado del día:** `[Trabajo Profundo / 4 Horas Productivas / Tareas Cortas]`
    
- **Intención Única del Día:** "Si hoy solo puedes terminar una cosa, debe ser: _[Insertar tarea clave extraída del contexto de mayor impacto]_".
    

#### 2. El Top 3 Crítico

1. **Impacto:** [Tarea prioritaria extraída del backlog]
    
2. **Desbloqueo:** [Acción urgente para que un miembro del equipo pueda seguir avanzando]
    
3. **Avance Crítico:** [Hito que empuja de forma sustancial un proyecto a largo plazo]
    

#### 3. Mapeo y Sincronización del Equipo (Análisis de WhatsApp e Info)

- **[Nombre Miembro 1]:** Revisar X cosa pendiente / Te tiene que enviar Y / Debes enviarle Z de forma urgente.
    
- **[Nombre Miembro 2]:** _Sin bloqueos detectados._
    

#### 4. Alertas de Estancamiento

- ⚠️ **Alerta:** La tarea "_[Nombre de la tarea]_" lleva **> 5 días** en tu lista sin registrar cambios.
    
- **Acciones sugeridas por la IA:** `[Delegar a X persona / Eliminar definitivamente / Desbloquear hoy mismo asignándole prioridad máxima]`.
    

#### 5. Matriz de Eisenhower del Día

- **Urgente e Importante (Hacer YA):**
    
    - _Tarea A (Ej: Resolver caída de servidor / Entregar propuesta cliente X)_
        
- **Importante pero NO Urgente (Planificar / Agendar):**
    
    - _Tarea B (Ej: Revisar estrategia Q3 / Actualizar documentación)_
        
- **Urgente pero NO Importante (Delegar):**
    
    - _Tarea C (Ej: Responder correo genérico de proveedores)_ $\rightarrow$ _Recomendación: Delegar en [Nombre]_
        
- **Ni Urgente ni Importante (Eliminar):**
    
    - _Tarea D (Ej: Limpieza de bandeja de spam antigua)_
        

## 5. Arquitectura del Prompt Principal (System Prompt)

Para lograr este comportamiento, el LLM debe ser inicializado con directrices muy claras. Aquí se detalla la estructura base del prompt:

Plaintext

```
Eres un Asistente Ejecutivo de Inteligencia Artificial de Élite, especializado en la optimización del tiempo, gestión de la atención y dirección de equipos para perfiles con TDAH o alta dispersión.

Tu objetivo es procesar las fuentes de información de entrada (Memoria, Calendario, Tareas de ayer y Backlog) y consolidar un informe diario ultra-estructurado, directo y accionable.

Reglas estrictas de procesamiento:
1. Filtra agresivamente el ruido de los chats de WhatsApp. Solo extrae hitos, dependencias o peticiones directas de acción.
2. Compara las horas de reuniones del calendario para clasificar el día de forma realista (Trabajo Profundo, 4h Productivas, Tareas Cortas). No sobrecargues un día lleno de reuniones con tareas complejas.
3. Identifica tareas estancadas comparando las fechas de creación o modificación (>5 días sin cambios) y ofrece una recomendación contundente (Delegar/Eliminar/Hacer).
4. Clasifica todo el set de tareas resultantes bajo la metodología de la Matriz de Eisenhower.
5. Usa un tono directo, motivador, profesional y sumamente claro. Evita introducciones corporativas innecesarias. Ve directo al grano.
```

## 6. Stack Tecnológico Sugerido para la Implementación

Desarrollo nativo:

        
- **Opción Programada (Robusta):**
    
    - **Backend:** _Python_ corriendo en el aquipo local.
    - 
    - **Base de datos:** _SQLite_ o _PostgreSQL_ para trazar el histórico de tareas y fechas de estancamiento.
        
    - **Automatización temporal:** Un servicio de tareas programadas tipo `cron`.
        

## 7. Métricas de Éxito del Sistema

El sistema se considera replicado con éxito si cumple con las siguientes condiciones:

1. **Cero Fricción por la Mañana:** El usuario no abre aplicaciones de gestión ni chats para enterarse de qué pasó; lee únicamente el Dashboard de la IA.
    
2. **Precisión del Contexto:** La IA no alucina tareas ni confunde qué miembros del equipo pidieron qué cosas en WhatsApp.
    
3. **Adaptabilidad Biológica:** El usuario siente que las tareas recomendadas coinciden con la energía real disponible según el tiempo libre de su calendario.
